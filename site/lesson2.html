数据清洗：把"脏数据"变干净

真实世界的数据几乎没有"拿来就能用"的：有重复行、有缺失值、有格式乱七八糟的字段。数据分析师 60% 的时间都花在清洗上。这一课我们把 15,346 行"毛坯数据"处理成 15,035 行"能直接分析的精装数据"。

核心技能 约 25 分钟 本课产出：15,035 行干净数据

本课目标

  • 学会给数据做"体检"：一行代码查出每列缺了多少
  • 掌握四板斧：去重、去合成数据、去无效行、修字段
  • 理解一个重要原则：不是所有缺失值都要删
  • 体验一次"数据体检"带来的意外发现

先想清楚：为什么必须清洗

重复行

同一小区被网页反复抓取，就会在数据里出现多次。不处理的话，它会被重复计算，把平均值"算重"。

合成数据

这份数据对个别没有数据的城市补了少量"编造"的行，已用 synthetic=1 标记。分析真实房价前必须剔掉，否则会污染结果。

缺失值

有些列信息不全（比如 8000 多行没有建成年份）。缺就缺了？还是要删行？——取决于你分析什么，本课会给出判断原则。

脏字段

"2023历下"把年份和区县挤在一起；"0.28%"和"持平"混在同一列。这种列要拆开、转成数字才能用。

一步步做

1

体检：每列缺了多少？

老规矩，每课代码都能独立运行。新建 step2_clean.py：

step2_clean.py · 第 1 段
import pandas as pd

df = pd.read_csv("toy_realestate_sample.csv", encoding="utf-8-sig")

# 逐列统计缺失（NaN）数量，从多到少排序
print(df.isna().sum().sort_values(ascending=False).head(6))
year_built 8041 nearby 7804 longitude 4062 latitude 4062 price_change 97 road 44 dtype: int64

解读：建成年份缺 8041 行、周边配套标签缺 7804 行、经纬度缺 4062 行。看到这个先别慌——

关键原则：按需清洗，不是见缺就删

缺失值要不要处理，取决于你这个分析用不用这列：

· 第 6 课要分析楼龄 → 到时只对 year_built 缺失的行做处理，现在不动；
· 第 8 课要画地图 → 到时只保留有经纬度的行；
· 但 price（价格）缺失的行，几乎所有分析都用不了 → 现在就删。

一刀切把 8000 多行全删掉会损失一半数据，那样反而错了。

2

第一板斧：去重

step2_clean.py · 第 2 段
# 先数一数有多少重复行
print("重复行数量：", df.duplicated().sum())

# 删掉它们，并立刻覆盖原表
df = df.drop_duplicates()
print("去重后：", df.shape)
重复行数量： 250 去重后： (15096, 18)

删掉 250 行完全一样的记录，15,346 → 15,096。drop_duplicates() 只删"每一列都相同"的行，所以不会误伤同小区的不同记录。

3

第二板斧：剔除合成数据

step2_clean.py · 第 3 段
# synthetic=1 的是补位用的编造数据，只留真实的
df = df[df["synthetic"] == 0]

# 第三板斧：删掉没有价格的行（没有价格就没法做房价分析）
df = df[df["price"].notna() & (df["price"] > 0)]

print("清洗后：", df.shape)
清洗后： (15035, 18)

又剔掉 44 行合成数据和 17 行无价格数据。现在表里 15,035 行，每一行都是真实小区 + 有价格。

df[条件] 是什么意思？

df[df["synthetic"] == 0] 读作"从 df 里挑出 synthetic 等于 0 的那些行"。方括号里放条件，就得到一张只含满足条件行的新表——这是 pandas 最核心的用法之一，第 5 课会大量使用。

4

第四板斧：修理两个"脏"字段

先看看脏在哪。区县列是这样的：

df["district"].head(3) 的值： '2023历下' '2023历下' '2018历下'

年份黏在区县前面，而且涨跌幅列里"0.28%"是文字、"持平"也是文字，没法直接算。用下面的代码各给它们"整容"：

step2_clean.py · 第 4 段
# ① 拆区县：把开头的连续 4 个数字删掉，"2023历下"→"历下"
df["district_clean"] = df["district"].astype(str).str.replace(
    r"^\d{4}", "", regex=True)

# ② 解析涨跌幅："0.28%"→0.28，"持平"→0.0，其他→NaN
def parse_change(v):
    if pd.isna(v):                # 空值
        return "NaN"          # 先占位，下面统一转回缺失
    s = str(v)
    if s in ("持平", "模拟"):  # 文字 → 数字 0
        return "0.0"
    return s.replace("%", "")   # "0.28%" → "0.28"

df["price_change_pct"] = (
    df["price_change"].apply(parse_change)   # 逐行套用上面的函数
      .replace("NaN", None)
      .astype("float64")                  # 文字 → 小数
)

print(df[["district", "district_clean", "price_change", "price_change_pct"]].head(3))
district district_clean price_change price_change_pct 0 2023历下 历下 0.28% 0.28 1 2023历下 历下 2.42% 2.42 2 2018历下 历下 0.57% 0.57

两列焕然一新：district_clean 是干净区县名，price_change_pct 是能直接求平均的数字。注意 r"^\d{4}" 是"正则表达式"，意思是"开头的 4 位数字"——现在不用深究，记住这个套路即可。

彩蛋：一次真实的"数据体检"发现

清洗字段时顺手做的一次抽查，发现了一个大问题——这正是数据清洗的价值。

把 district_clean 做出来后，我们自然会想检查"每个城市都有哪些区县"。于是看了一眼西安：

命令
# 看西安的行都来自哪些"区县"
print(df[df["city"] == "西安"]["district_clean"].value_counts())
离石 42 孝义 21 文水 7 中阳 2 汾阳 2 柳林 2 兴县 1 临县 1 Name: district_clean, dtype: int64

🔍 发现问题了没？

离石、孝义、文水……这些根本不是西安的区县，全部是山西吕梁的！这份数据在抓取时把西安和吕梁弄串了。如果直接拿去分析"西安各区县房价"，结论会错得离谱。

两个教训：① 分析前永远做一次这类"常识核对"（city 和 district 对不对得上）；② 发现某列数据可疑时，宁可不分析它，也不要硬编一个结论。
